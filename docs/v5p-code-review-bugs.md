# V5-P / AI-Midi 代码 Review Bug 记录

> 这份文档只记录代码 Review 中已经确认的行为问题，不承担架构设计说明。
> 用户确认修订策略后，再把对应条目转为实现任务。

## 记录规则

- 只登记可以从当前代码路径推导出明确错误行为的问题；
- 用户明确否定的候选不保留；
- 每个条目包含触发路径、影响和修订方向；
- 本文档不代表实现已经修复。

## 已确认问题

- `BUG-012`：单独发布带 A 区引用的 B SynthesisUnit 时，不会递归发布 A，跨项目同步后 A 可能失效。暂缓原因：需要先确定 A 不在 Resource、A 已全局发布及中途失败时的原子事务语义。
- `BUG-043`：WebSocket 注册超时路径只记录服务端日志，没有向前端发送明确失败状态或结束消息；前端已经进入 running 的生成任务可能一直停留在进行中。暂缓原因：HTTP 已返回后且 WS 从未建立，现有协议没有可用的失败通知通道。
- `BUG-065`：Global Resource 发布先逐个写入 staged Blob，后续校验或 catalog 写入失败时没有清理已写入文件。暂缓原因：当前 staged 与正式 Blob 共用目录和哈希路径，必须先拆分独立 staging 区后才能安全清理。

## 后续处理

每个 BUG 由用户先确认真实影响和修订策略。确认后再：

1. 在实现文档中补充最终行为合同；
2. 修改语义命令或事务边界；
3. 增加必要的轻量回归测试；
4. 更新本记录的处理状态。
