# V5-P H Token 中文目录

> 状态：基于 2026-08-10 当前训练/runtime 源码整理的编辑器设计资产。
> 目标读者：中国用户；允许用户完全不认识假名和 IPA。
> 本文覆盖 dense runtime token ID `0..366`。它不是新的 tokenizer，也不改变 checkpoint 合同。

## 1. 为什么需要这份目录

H lane 里的 token 不能只显示一个 IPA 符号或整数 ID。正式界面应按以下优先级解释：

```text
中文名称 / 发音作用
  -> 中文近似说明（明确只是近似）
  -> 所属 mora 的 romaji
  -> kana（保留原文，但不要求用户看懂）
  -> runtime symbol
  -> runtime token ID / vocab hash
```

例如当前前端的真实结果：

```text
き      -> k | i
きゃ    -> kj | a
し      -> ɕ | i
ち      -> tɕ | i
つ      -> tsɯ | ɯ
ふ      -> ɸ | ɯ
ん      -> ɴ
がっこう -> g | a | q | k | o | o
```

面向用户不应只写 `tɕ`，而应写成类似：

```text
chi 辅音
近似中文“七”的起始音
常见 romaji: chi / cha / chu / cho
原文 kana: ち / ちゃ / ちゅ / ちょ
runtime: tɕ · ID 333
```

中文谐音只帮助定位，不能作为音素定义，也不能写回 control data。

## 2. ID 口径

本文使用 **dense runtime token ID**：

```text
vocab.json raw ID 0..362
  -> CNENTokenizer +1
  -> dense H/text token ID 1..363
```

另外：

```text
0   = dense filler / 历史 PAD、V
364 = <PUNCT>，初始化时追加但当前无使用路径
365 = <SEP>
366 = <PUL>，V4H/V5-P 扩展
```

旧文档中若写 `ɯ=318`、`tɕ=332`，使用的是 vocab raw ID；编辑器和 runner 中对应为
`ɯ=319`、`tɕ=333`。UI、持久化 schema 和审计一律保存 runtime ID，同时绑定 vocab hash。

## 3. Token 不等于单个 IPA 字符

Tokenizer 按 `|` 切分。分隔符之间的整个字符串才是一个原子 token：

```text
kj       一个 token，不是 k + j
tɕ       一个 token，不是 t + ɕ
tsɯ      一个 token，不是 t + s + ɯ
çj      一个 token，且 ç 使用组合 Unicode
p⁼wo↓↑  一个带普通话三声轮廓的完整复合 token
```

因此 Token Editor 不能按 Unicode 字符移动或删除内部符号。

## 4. 当前源码事实与历史文档差异

- 当前 `package_v4c_finetune/g2p/japanese.py` 实测 `じ -> dʑ|i`，即 runtime ID 329；
  历史 V2 计划中“当前使用 `ʑ`”的记录已与现源码不一致。
- 当前 kana 正常路径常把长音展开为重复元音，例如 `カー -> k|a|a`；词表中的 `aː/ɯː/eː/ː`
  仍需解释和诊断，但不能假定每次长音都使用这些 token。
- `g`（ASCII，ID 328）与 `ɡ`（IPA 字符，ID 33）不同。
- `ç`（c + U+0327，ID 324）与 `ç`（U+00E7，ID 69）不同。
- 本机 V5-P 40K final 的 checkpoint metadata 与 optimizer 证据已用于本目录；正式接入时仍须绑定
  完整 runtime bundle、vocab hash 与 adapter hash 后再次冻结版本。

## 5. V5-P 40K 训练暴露证据

完整目录中的“V5-P 40K 训练”回答的是：该 runtime token 是否在目标
`V5P_40K_EMA/step_040000_final.pt` 的 joint Phase B 中实际进入 text embedding 并留下优化器动量。

证据口径：

```text
runtime token ID = k
embedding row = k + 1
row 0 = CFG 无条件分支，不对应任何 runtime token
```

- checkpoint SHA256：
  `3a532f5bd5965dff7d011996b7ca72d7884c5494a2d44d6c28b0bab21bace96c`；
- checkpoint schema：`v5p_training_checkpoint_v1`，step 40000，`phase=joint`；
- checkpoint metadata 绑定 frozen `train_mixed.json` SHA256：
  `f4ed5804251691348b19c88e2aa26c5fcc9dcd820ccc032aecd220132bb2ee98`；
- Phase B metadata 明确记录 `optimizer_policy=fresh`，因此 final optimizer 不继承 Official/V4 的旧动量；
- text embedding optimizer state key 4，shape `[374, 512]`；
- 46 个 embedding row 的 `exp_avg` 非零，其中 row 0 是 CFG，剩余 45 个对应实际 runtime token；
- 45 个 runtime token 可拆为：36 个发音 token、6 个歌词标点 token、3 个 dense/runtime 特殊值
  `0 / SEP / PUL`；
- 目录中的“是”表示对应 row 的 `abs(exp_avg).sum() > 0`；
- “否”表示对应 row 在 final optimizer 中精确为零；
- 42 个普通歌词 token 的非零 row 与本地 Short H train manifest 的实际 token 集完全一致；
- `0`、`SEP=365`、`PUL=366` 的 row 也非零，证明三者进入过 V5-P 训练；
- `PUNCT=364` 的 row 为零，证明它没有进入 V5-P joint 训练。

这列只描述 **V5-P 40K 这一阶段**。“否”不等于该 embedding 在 Official 中英预训练或更早 V4
谱系中从未见过；也不表示把未见 token 塞入当前日语 control 就是安全的。编辑器应把 V5-P 未见
token 默认隐藏，并在 Raw override 时给出强警告。

因此普通日语 pronunciation palette 的训练内默认候选不是 45 个，而是下面 36 个发音 token：

```text
p b t d k v s z m n j i ɾ a o
ɯ e ç ɸ ɰᵝ ɴ g dʑ q
bj tɕ dej gj çj kj mj nj pj ɾj ɕ tsɯ
```

标点 `, . ? ! ' …` 应归入歌词结构/标点组；`0 / SEP / PUL` 应归入 runtime 组，均不能混入普通
发音替换器。

当前本机没有保存上述 frozen `train_mixed.json` 本体，因此本文不伪造 V5-P mixed pool 的逐 token
精确出现次数。是否见过由 final optimizer 直接证明；以后取回冻结 manifest 后，再追加 source
occurrence count、sample count 和 phrase count。

也暂不增加“模型全生命周期见过”这一列。现有 Official checkpoint 审计只保留了区域汇总：

```text
EN/shared 1..74: 60 / 74 rows 有动量
CN 75..318:      160 / 244 rows 有动量
JA 319..346:     1 / 28 rows 有微弱动量
Rare 347..363:   1 / 17 rows 有微弱动量
PAD 与 SEP:      有动量
PUNCT:           无动量
```

这些汇总不足以把 Official 状态可靠摊到每个具体 ID。取得 Official checkpoint optimizer 或原始训练
token manifest 后，才能追加逐项的 `Official seen`；在此之前一律标为“未逐项核实”，不能根据语言
区间猜测。

## 6. 编辑器使用规则

普通日语 VocalPart 中：

- 默认 palette 只展示当前 Japanese G2P 可达 token 和上下文允许的替换；
- 中文、英语和罕见多语言 token 默认隐藏，只在 Raw/Diagnostic 中可查；
- `0` 通过“清除显式事件”产生，不能命名为静音；
- `SEP` 由 phrase compiler 管理；
- `PUL` 由 runtime fallback 管理；
- `PUNCT=364` 禁止选择；
- 用户替换歌词 token 必须创建 pronunciation override；
- Inspector 必须同时显示中文解释、symbol、ID、来源、vocab hash 与原始 tokenizer 建议。
